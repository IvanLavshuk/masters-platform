# Протокол экспертного разбора проектных материалов

Дата: 24 ноября 2026 года. Объект: исходное ТЗ ЛР 2, UML и шесть макетов ЛР 3, спецификация API и модель данных ЛР 4. Метод: сопоставление требований с представленными сценариями и экранами. Проверка проводится по документам; наблюдения за реальными пользователями и испытания серверного приложения не выполнялись.

| Проверка | Основание и наблюдение | Результат для итерации |
|---|---|---|
| R-01 Отмена опубликованного заказа | М-03 и М-07 разрешают отмену до выбора исполнителя. На экранах 1–6 не детализированы подтверждение отмены заказа и сохранение причины. «Отмена» в форме создания относится к выходу из формы и не описывает всю операцию отмены опубликованного заказа. | FB-01 уточняет существующую функцию: подтверждение и причина; введено М-40. |
| R-02 Неопределённый результат оплаты | М-13 и API ЛР 4 предусматривают оплату и состояние pending. В исходных шести макетах нет экрана, поясняющего потерю ответа, безопасный повтор одной попытки и создание новой попытки после подтверждённого неуспеха. | FB-02 детализирует интерфейс и клиентский контракт; введено М-41. |
| R-03 Подтверждение выполнения | Исходное М-07 и Use Case позволяют исполнителю самостоятельно завершить заказ. Это соответствует исходному ТЗ. Учебный заказчик предлагает дополнительное подтверждение результата получателем услуги. | FB-03 является новым моделируемым требованием, а не обнаруженным нарушением исходного ТЗ; введено М-42 и состояние awaiting_confirmation. |

Учебные формулировки не являются фактическими замечаниями преподавателя. Если преподаватель предоставит собственный фидбек, он используется для уточнения состава итерации. Повторная проверка состоит в сопоставлении М-40–М-42 с актуальными Use Case, Activity, Sequence, API и ER. Интерактивные сценарии макета проверяются в браузере при выполнении инструкции; до этого они не отмечаются пройденными.
