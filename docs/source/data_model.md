# 4 Модель данных

Включены обе исходные ER-диаграммы из ЛР 4 с сохранением нотации и расположения сущностей. Они показывают предметную основу: 11 сущностей и 12 таблиц. Изменения редакции 1.1 приведены после рисунков в таблице расширений и в schema.sql. Три технические таблицы обеспечивают надёжность платёжного контракта; вместе с исходными таблицами проектное DDL содержит 15 таблиц.

## Расширения исходной модели в редакции 1.1

| Элемент исходной модели | Изменение |

| --- | --- |

| order_status_history | Добавлено reason для причины явной отмены заказа (М-40). |

| orders.status | Добавлено awaiting_confirmation между in_progress и completed (М-42). |

| payments | Уточнены customer_id, currency=BYN и confirmation_url для согласования с Payment в API. |

| payment_requests | Новая техническая таблица: caller_id, operation, ключ, хеш запроса и payment_id. Уникальность по вызывающему компоненту, операции и ключу. |

| payment_delivery_jobs | Новая техническая таблица: event_id, платёж, неизменяемый payload, число попыток, время повторной доставки, время завершения и ошибка. |

| processed_payment_events | Новая техническая таблица: event_id, платёж, заказ, хеш и принятый результат. Обеспечивает обработку повторов без второго эффекта. |

## Связи и ограничения

Сохранены связи исходной модели: users — executors, заказчик — orders, orders — responses/messages/history/payments/reviews; executors и categories связаны через executor_categories. Исполнитель заказа определяется единственным выбранным откликом. promotions.executor_id ссылается на executors, banners.user_id — на users. Новые технические таблицы связаны с payments, а processed_payment_events дополнительно с orders.

Частичный уникальный индекс допускает один выбранный отклик на заказ; второй ограничивает pending/succeeded-платежи одного заказа. Отзыв на заказ единственный, оценка 1–5. Изменение статуса и запись истории сохраняются атомарно. Денежные суммы хранятся как numeric, а в API передаются строками; время в DDL — timestamptz с передачей UTC. На исходных рисунках сохранены обобщённые типы integer и timestamp; конкретные типы и ограничения реализации уточняются schema.sql.

Расширения не заменяют исходные предметные диаграммы. Полный состав полей и внешних ключей актуальной редакции приведён в docs/source/schema.sql; применение DDL к работающей базе в ЛР 5 не выполнялось.
