# Платформа поиска бытовых мастеров и специалистов

Учебный проект по дисциплине «Принципы проектирования систем человекомашинного взаимодействия». Платформа для Республики Беларусь объединяет заказчиков и исполнителей бытовых услуг: поиск мастеров, публикацию заказов, отклики, выбор исполнителя, чат, выполнение заказа, оплату и подтверждённые отзывы. Первоначальная территория запуска — Минск.

## Состояние проекта

Подготовлены проектные материалы и структура будущих модулей. Серверные функции, база приложения и сборочные файлы пока не реализованы. Инструкция ниже описывает предполагаемую реализацию и не обещает запуск отсутствующего приложения.

## Выбранные технологии

- Backend: Java 25, Spring Boot, Gradle.
- Основное хранилище: PostgreSQL 17.
- Веб-клиент: React и TypeScript.
- Мобильный клиент: Flutter и Dart.
- Инфраструктура разработки: Git, Docker Compose.
- Контракты: HTTPS, REST, JSON, OpenAPI 3.1.

Стек выбран для структуры проекта в ЛР 5; предыдущие работы не закрепляли конкретные фреймворки. Серверная часть сохраняет функциональные компоненты и общий слой данных исходной архитектуры. Платёжный компонент применяет паттерн «Фасад». Брокер сообщений не вводится.

## Структура

`docs/` — проектные документы; `prototypes/` — макеты; `src/backend/modules/` — будущие модули серверной части; `src/web/` и `src/mobile/` — клиенты; `config/` — примеры конфигурации.

## Как начать работу

1. Клонировать репозиторий: `git clone https://github.com/IvanLavshuk/masters-platform.git`.
2. Прочитать ТЗ и архитектуру, проверить назначение модулей в `src/`.
3. Создать ветку: `git switch -c feature/имя-задачи`.
4. Для настройки окружения скопировать `config/.env.example` в `config/.env` и задать собственный пароль. Локальный `.env` исключён из Git.
5. Зафиксировать связанные изменения одним понятным коммитом или несколькими коммитами и открыть Pull Request в `main`.

## Предполагаемые сборка и запуск

После создания приложения backend получит Gradle Wrapper: сборка `gradlew.bat build`, запуск `gradlew.bat bootRun` из его каталога. После создания веб-клиента появятся `package.json` и lock-файл: установка `npm ci`, запуск `npm run dev`. Для мобильного приложения после создания Flutter-проекта используются `flutter pub get` и `flutter run`. Сейчас эти команды для приложения не выполняются: соответствующие проекты ещё не сгенерированы.

Пример PostgreSQL можно запускать отдельно из корня репозитория после заполнения `config/.env`: `docker compose --env-file config/.env -f config/compose.yaml up -d`. Это запускает только БД, не платформу. Для самой лабораторной запуск БД не требуется.
